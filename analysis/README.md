# Analysis notebooks

Notebooks for the SpMV streaming results (committed without outputs; execute them on the data, see Run): `spmv_barrier_remeasure.ipynb` (the 2026-10-07 barrier re-measure) and `spmv_scaling.ipynb` (2026-10-09: setup strips synced timing, weak scaling to the full wafer, wall time before/after). The host↔wafer microbenchmarks M1–M10 and their
notebooks moved to [hlrs-fcg/cs3-microbench](https://github.com/hlrs-fcg/cs3-microbench) (private repository) (`analysis/` there). Analysis only: nothing here touches the cluster or the synced tree.

## Where the data comes from

The notebooks read result CSVs from `cluster/results/data/` (or `$SPMV_DATA`). The CSVs of the 2026-10
development runs are not in the tree any more; they are on the branch `archive/dev-results-2026-10` of the
private development repository. To re-run the notebooks on them:

```sh
git worktree add ../spmv-dev-results archive/dev-results-2026-10
SPMV_DATA=../spmv-dev-results/cluster/results/data uv run --no-project ...   # see Run, below
```

```
2026-10-07_barrier-remeasure.csv  SpMV header / valtask / column runs, barrier-verified
2026-10-07_s1-column-matrix.csv   S1 follow-up (column mode, serialization, valtask column)
2026-10-08_fullwafer.csv, 2026-10-09_{weak-scaling,setup-strips,dan56,xsys-check}.csv   the scaling runs
```

The v2.0 benchmarks are re-run from the tagged commit and written to `cluster/results/data/`; the
notebooks are then re-executed on those. A notebook whose CSV does not exist still runs: its Result cell
prints "no data yet".

## Run

Always `uv`, never a hand-made venv. The project lock fails on macOS, so use `--no-project`. From the repo root:

```sh
uv run --no-project --python 3.11 --with numpy --with pandas --with matplotlib --with jupyter --with nbconvert --with nbformat \
  jupyter nbconvert --to notebook --execute --inplace analysis/spmv_barrier_remeasure.ipynb analysis/spmv_scaling.ipynb
```

To read the saved charts in JupyterLab, trust the notebooks once after each re-execution (untrusted notebooks don't render SVG output):

```sh
cd analysis && uv run --no-project --python 3.11 --with jupyterlab jupyter trust *.ipynb
cd analysis && uv run --no-project --python 3.11 --with numpy --with pandas --with matplotlib --with jupyterlab jupyter lab
```

Execute the notebook before committing so the committed `.ipynb` contains outputs. It is generated by
`analysis/_build_notebooks.py` (so the four-part structure stays identical); edit the text there, not in the `.ipynb`:

```sh
uv run --no-project --python 3.11 --with nbformat python analysis/_build_notebooks.py
```

Rebuilding resets outputs; re-execute afterwards. The "What that means" text is dated and names the data it was written
from; the Result cells update on re-run, **the prose does not**.

## Structure of every notebook

One section per question, each with: **Hypothesis** (written before looking, with a prediction and a falsifier) → **Result**
(n, min, median, max, timing basis, number of excluded rows) → **What that means** → **What the vendor says** (verbatim quotes
with source; agreement or contradiction stated).

Rules applied by `lib.py`: rows that failed or did not verify are excluded and counted; only barrier-closed
times (`corrected_time`, `stream_time_corrected`, `setup_h2d_time_corrected`) are used for rates; host-return times appear only
to show their gap. The 10-07 SpMV CSVs have no system column, so rows cannot be filtered by system (the one known bad-system run never produced a row).

`lib.py` holds the loaders (`load_spmv`, `valid_spmv`), `summarize` (n/min/median/max) and the plot helpers (neutral grey text
on a transparent background, colour-blind-safe palette, so figures read in light and dark themes). `vendor_sources/` holds a
dated snapshot of a vendor page (`2026-10-08_tensor-streaming.md`); notebooks cite `[SDK]:<line>` into it.
`*.ipynb` is git-ignored except `analysis/*.ipynb`; check with `git ls-files analysis`.
